Full Loop Tutorial

This tutorial walks through a complete Descartes workflow: from PRD to implementation with validation, demonstrating all major features.

Scenario

We'll implement a user authentication feature for a Rust web API. The workflow includes:

  1. Writing a PRD
  2. Parsing into SCUD tasks
  3. Executing with fresh-context agents
  4. Validating between waves
  5. Handling failures and retries
1

Create the PRD

Start with a Product Requirements Document describing the feature:

cat > auth-feature.md << 'EOF'
# User Authentication Feature

## Overview
Add JWT-based authentication to the REST API.

## Requirements

### 1. User Registration
- POST /api/register endpoint
- Accept email, password, name
- Hash passwords with bcrypt
- Return user object (without password)

### 2. User Login
- POST /api/login endpoint
- Accept email and password
- Validate credentials
- Return JWT token on success

### 3. Protected Routes Middleware
- Create authentication middleware
- Extract and validate JWT from Authorization header
- Attach user to request context
- Return 401 for invalid/missing tokens

### 4. User Profile Endpoint
- GET /api/me endpoint (protected)
- Return current user's profile

## Technical Notes
- Use `jsonwebtoken` crate for JWT
- Use `bcrypt` crate for password hashing
- Token expiry: 24 hours
EOF

Handle Validation Failures

When validation fails, Descartes marks tasks for retry:

Wave 2/3 ━━━━━━━━━━━━━━━━━━━━ 1 task [3] Protected Routes Middleware Spawning claude-code agent (opus)... ✓ Completed in 48s Running validation: cargo test Running 9 tests ✗ test auth::middleware::test_invalid_token ... FAILED Validation failed! Marking [3] as failed Retrying failed tasks... [3] Protected Routes Middleware (retry 1/3) Including failure context in spec Spawning fresh agent... ✓ Completed in 61s Running validation: cargo test ✓ All tests passed
Fresh Context on Retry When a task fails validation, Descartes spawns a completely new agent with:
  • The original task spec
  • The validation failure output
  • A fresh context (no accumulated state)
5

Add Implementation Context

Provide additional context with --plan and --spec-file:

# Create an implementation plan
cat > implementation-plan.md << 'EOF'
# Auth Implementation Plan

## Task 1: User Registration
- Add User model in src/models/user.rs
- Add registration handler in src/handlers/auth.rs
- Use existing database pool from AppState

## Task 2: User Login
- Reuse User model from Task 1
- Add JWT generation in src/utils/jwt.rs
- Set token expiry from config

## Task 3: Middleware
- Create src/middleware/auth.rs
- Use tower middleware pattern
- Extract user ID from JWT claims

## Task 4: Profile
- Add handler in src/handlers/user.rs
- Use middleware to get current user
EOF

# Run with additional context
descartes ralph \
    --scud-tag auth \
    --plan implementation-plan.md \
    --spec-file ./docs/API_SPEC.md \
    --verify "cargo test && cargo clippy"

The spec for each task will include:

  • Task details from SCUD
  • Relevant section from implementation-plan.md
  • Contents of API_SPEC.md

Monitor with the GUI

Use the GUI for visual control:

# Terminal 1: Start the GUI
descartes-gui

# Terminal 2: Start execution (GUI will show progress)
descartes ralph --scud-tag auth

In the GUI:

  1. Waves view: See all tasks organized by wave
  2. Click Start: Begin individual tasks
  3. Agents view: Pause/Resume/Cancel running agents
  4. Output view: Watch agent responses stream

Advanced: Using Different Harnesses

Fast Iteration with OpenCode

# Use OpenCode + Grok for fast iteration
descartes ralph \
    --scud-tag auth \
    --harness opencode \
    --model grok-code-fast-1 \
    --verify "cargo check"  # Faster validation

Mixed Harness Strategy

# Fast harness for simple tasks
descartes ralph --scud-tag setup --harness opencode

# Smart harness for complex implementation
descartes ralph --scud-tag auth --harness claude-code --model opus

# Fast harness for tests and docs
descartes ralph --scud-tag polish --harness opencode

Best Practices

PRD Structure
  • Number your requirements clearly
  • Keep each requirement focused and testable
  • Include technical notes for implementation hints
  • Specify dependencies explicitly
Validation Commands
  • Always include cargo test or equivalent
  • Add cargo clippy for lint checking
  • Use cargo check for fast compile verification
  • Consider cargo fmt --check for style
Token Budget
  • Default spec budget is 5000 tokens
  • Increase with --max-spec-tokens for complex tasks
  • Keep implementation plans concise and relevant
  • Use task-specific sections in your plan document

Troubleshooting

Tasks stuck in pending

# Check task dependencies
scud show <task-id>

# View waves to see blocking tasks
descartes waves

Validation always fails

# Run validation manually to debug
cargo test

# Check if tests require setup
cargo test -- --nocapture

Agent produces incorrect code

# Review the transcript
descartes show <session-id>

# Check the spec that was sent
descartes show <session-id> | grep "Spec:"

# Retry with more context
descartes ralph --scud-tag feature \
    --spec-file ./more-context.md
