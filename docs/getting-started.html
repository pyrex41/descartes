Getting Started

This guide walks you through installing Descartes, configuring your environment, and running your first AI-orchestrated workflow.

Installation

From crates.io (Recommended)

# Install the CLI
cargo install descartes-cli

# Install the GUI (optional)
cargo install descartes-gui

From Source

git clone https://github.com/pyrex41/descartes
cd descartes

# Build CLI
cd descartes && cargo build --release

# Build GUI
cd ../descartes-gui && cargo build --release

System Dependencies

Required for all platforms:

  • Rust 1.75+
  • protoc (protobuf compiler) - required by BAML
  • Node.js with npx - for BAML code generation
# macOS
brew install protobuf

# Ubuntu/Debian
sudo apt install protobuf-compiler

# Linux (GUI only)
sudo apt install libxkbcommon-dev libwayland-dev

Configuration

Environment Variables

Variable Description Required
ANTHROPIC_API_KEY API key for Claude models Yes (for Claude harness)
OPENAI_API_KEY API key for OpenAI/Codex models Yes (for Codex harness)
XAI_API_KEY API key for xAI/Grok models (SCUD) Optional
DESCARTES_HARNESS Default harness: claude-code, opencode, codex No (defaults to claude-code)
DESCARTES_MODEL Default model (opus, sonnet, etc.) No 
# Add to ~/.bashrc or ~/.zshrc
export ANTHROPIC_API_KEY=sk-ant-api03-...

# Or use a .env file in your project
echo "ANTHROPIC_API_KEY=sk-ant-api03-..." > .env

SCUD Setup

Descartes uses SCUD for task management. Initialize SCUD in your project:

# Install SCUD
cargo install scud-cli

# Initialize in your project
cd your-project
scud warmup

This creates a .scud/ directory with task storage and configuration.

Your First Run

Option 1: Execute from PRD

Start with a Product Requirements Document:

# Create a simple PRD
cat > feature.md << 'EOF'
# User Authentication Feature

## Requirements
1. Add login form with email/password
2. Implement JWT token generation
3. Add logout endpoint
4. Create protected route middleware
EOF

# Parse and execute
descartes ralph --prd feature.md

Descartes will:

  1. Parse the PRD into SCUD tasks
  2. Expand complex tasks into subtasks
  3. Compute execution waves
  4. Execute each task with a fresh agent
  5. Run validation between waves

Option 2: Use Existing SCUD Tasks

# Create tasks manually
scud add "Implement login form" --tag auth
scud add "Add JWT middleware" --tag auth --depends-on 1

# Or parse a PRD with SCUD directly
scud parse feature.md --tag auth

# Then execute with Descartes
descartes ralph --scud-tag auth

Preview Without Executing

# Dry run shows the execution plan
descartes ralph --scud-tag auth --dry-run

# Output:
# Wave 1: [1] Implement login form
# Wave 2: [2] Add JWT middleware (depends on 1)

Understanding the Output

During execution, Descartes displays:

Wave 1/3 ━━━━━━━━━━━━━━━━━━━━ 2/2 tasks
  [1] Implement login form ............ Done
  [2] Create user model ............... Done

Running validation: cargo test
  ✓ All tests passed

Wave 2/3 ━━━━━━━━━━━━━━━━━━━━ 1/1 tasks
  [3] Add JWT middleware .............. Running
Fresh Context Per Task Each task gets a completely fresh agent session. This prevents context drift and ensures reproducible execution. The agent receives only the task spec, not history from previous tasks.
